# 분석 계획 (실행 결과를 보기 전에 고정)

이 문서의 기준은 v1.4 재시험의 결과를 보기 전에 정한다. 수치는 모두 작성자의 사전 선언이며 데이터에서 도출한 값이 아니다. 결과를 본 뒤 기준을 바꾸면 그 사실을 보고서에 적는다.

## 1. 무엇을 주장하려는가 (주장 단위)
- 비교 대상은 같은 11개 approach(DIRECT 1, 템플릿 5 x +G, 템플릿 5 x +R2)의 프롬프트 버전 v1.3(관행 미명시)과 v1.4(관행 명시)다. approach는 늘리지 않는다.
- 관행의 출처: FRET 공식 문서 condition.md는 조건을 두 종류로 정의한다. `upon`(또는 when, where, if)는 조건이 거짓에서 참이 되는 시점의 요구(regular), `whenever`는 조건이 참인 동안 매번 응답이 성립하는 요구(holding)다. 어느 쪽이 의도인지는 NL이 정하지 않는다(NASA 저자도 AP-003c에서 시뮬레이션으로 의도를 확인했다: Mavridou et al., IEEE RE 2020, NTRS 20205000433).
- v1.3 결과는 "관행을 명시하지 않았을 때"의 값으로 보존하고, v1.4는 "관행을 NASA 원문 인용으로 명시했을 때"의 값이다. 두 조건은 모든 approach에 공통이므로 RQ2(템플릿 효과)는 관행이라는 교란을 공통으로 준 상태에서 읽는다.

## 2. 가설과 판정 기준
단위: 항목(item). 한 항목의 부분과 반복은 독립이 아니므로, approach마다 항목별 비율(반복 x 부분 평균)을 만들고 v1.4가 v1.3보다 좋아진 항목 수를 정확 부호 검정(한쪽, 동률 제외, 유의수준 0.05)한다. 13개 항목에서 동률 없이 10개 이상이 좋아지면 통과(p = 0.046). 48개 항목에서는 31개 이상(p = 0.030). `tools/compare_runs.py`가 이 규칙을 그대로 계산한다.
- H1 (기제): 생성 문장의 읽기(EDGE, EVERY_TIME)와 정규화 타이밍이 기준 대표 버전과 같아지는 비율이 오른다. 지표는 `reading_same`, `ntiming_same`(분석기의 결정 지점, 읽기는 공식 파서로 확인한 동치 `whenever c immediately r` = `always satisfy c => r`에 근거해 의미 기준으로 정규화). 읽기(`reading_same`)는 +R2에서 조건 키워드를 스크립트가 쓰므로 모델이 정하는 6개 approach(DIRECT, 5 x +G)에서 5개 이상 통과해야 하고(+R2 5개는 조립이 의도대로 작동하는지의 점검값으로만 보고), 타이밍(`ntiming_same`)은 11개 중 8개 이상 통과해야 한다. 둘 다 충족하면 H1 지지.
- H2 (결과): 엄격 성공(아래 정의)이 오른다. 같은 방식으로 8개 이상에서 통과하면 H2 지지.
- 사전 결정 규칙
  - H1과 H2 지지: v1.4를 주 조건으로, v1.3을 "관행 미명시" 조건으로 보고한다.
  - H1만 지지: 읽기는 움직였으나 성공은 움직이지 않았다. 다음은 분석기의 EXPRESSION과 INSTRUMENT 원인 표를 읽는 것이고 그 전에 도구를 바꾸지 않는다.
  - H1 기각: 의도 선언이 읽기를 움직이지 못했다. 가설 기각이며 같은 항목에서 새 사전 가설 없이 재시도하지 않는다.
- 이 기준은 FSM 13항목(진단에 쓴 항목)에서 검정할 때 기제 확인일 뿐 일반화가 아니다. 일반화 점검은 비 FSM 48항목(confirm, v1.3과 v1.4 모두 1회씩)에서 같은 기준으로 한다. 48항목은 v4~v8에서 이미 관찰된 자료이지만 v1.4의 도구에는 그 관찰에서 도출한 결정이 없다(5절). 이 항목들의 이전 결과를 본 적이 있다는 사실은 보고서에 적는다.

## 3. 성공 지표 정의
- 관대 성공(lenient): 판정기 역할이 SAME 또는 PROOF. 판정기 v1.2의 정의 그대로다.
- 엄격 성공(strict): 관대 성공이면서 생성식이 만족 가능하고(aux 질의 `gen_sat`), 사전 이름 정렬을 넘는 자유 개명이 없는 것. 근거: 판정기 대조에서 항상 거짓인 명세(`f & !f`)가 기준 112행 중 112행(100%, NuSMV 2.5.4, 윈도 상한 512)에서 PROOF로 판정되었다(z3 유계 지평 8에서는 104행). 그래서 관대 성공만으로는 모순식도 성공으로 센다. 엄격 성공이 이를 걸러낸다(v1.3 FSM 429부분: 관대 18, 엄격 17, 모순 1건 제거).
- SAME만: 따로 보고한다. v1.3 FSM에서 관대 성공 18개 중 SAME은 0이고 모두 PROOF였다.
- PROOF 분리 보고: PROOF는 생성이 기준보다 강하다(생성이 기준을 함의)는 판정기 v1.2의 정의다. 만족 불가능한 강함은 엄격 성공이 제거한다. 만족 가능하지만 기준보다 지나치게 강한 생성은 관대와 엄격 모두 성공으로 세므로 `SAME만` 지표를 항상 나란히 보고하고, 주 결과 해석은 SAME만과 엄격 성공 둘의 방향이 같을 때만 지지로 읽는다(사전 규칙).
- 분모는 항상 모든 부분이다. UND, N/M, 파서 거부, 문장 없음 포함. 실패를 제외한 성공률을 주 결과로 쓰지 않는다.

## 4. 도구 타당성 보고 (모든 접근 비교 앞에 싣는다)
- 양성 대조(기준 자체, 이중 부정, 자기 중복 논리곱)에서 SAME이 아닌 비율: NuSMV 2.5.4 기준 윈도 상한 128에서는 112행 중 3행(NN-N3 두 부분, NN-N4, 윈도 128 초과)이었고, 같은 판정기의 `--cap 512`로 112행 모두 SAME이다(0/112). z3에서 판정 불가였던 REG-N01~N05는 NuSMV에서 해소되었다. 따라서 v1.4 판정은 `CAP=512`, 엔진 NuSMV로 하고, 비교 기준인 v1.3 결과도 같은 조건으로 판정기만 다시 돌린다(LLM 호출 없음). 어떤 항목도 구조적 실패 층으로 제외하지 않는다.
- 음성 대조: 항진식(`f | !f`) 성공 0건, 부정 0건, 모순식 112건(위 설명, 엄격 성공이 걸러냄), 같은 항목 내 다른 부분 기준과의 비교 18.2%(33부분 중 6, 정보용: 같은 항목의 서로 다른 부분이 실제로 동치인 경우가 있음. 항목 NN-N3 등).
- 층화 보고: 짝짓기 근거(`rationale` / `id_order`), NL과 연결된 기준 행이 없는 항목(휴리스틱), 기준 내 충돌 정의가 있는 항목, 판정기가 기준 자신과 비교할 수 없는 항목. 데이터는 수정하지 않는다.
- 원인 라벨: 엄격 성공이 아닌 모든 부분에 사전 순서로 원인 하나를 붙이고(합계 = 실패 수) 해당하는 모든 라벨도 함께 남긴다. 순서: PIPELINE, INSTRUMENT_CEILING, INSTRUMENT_UND_NM, INSTRUMENT_STRICT, DATA, TEMPLATE_INFO_LOSS(단계 A가 `unmapped_content`를 기록), DECISION(읽기, 타이밍, 범위 중 다른 것), EXPRESSION(결정 지점은 같고 식이 다름).

## 5. 도구 결정의 근거 (모든 DEFAULT 규칙을 닫은 방식)
규칙 52개 중 DEFAULT 39개에 대해 `tools/ownership_table.py`가 코드에서 다음을 계산하고 lint P-1b가 0 위반을 강제한다.
- 활성 30개: 근거가 있다. 근거 유형은 (a) FRET 공식 문서 원문 인용(34개 인용이 문서와 글자 단위로 일치), (b) 공식 파서 검증(`tools/rule_semantics_check.py`, NuSMV로 LTL 동치 확인), (c) 목표 형식이 강제하는 것(응답 형식은 `satisfy BEXP` 하나, 구성요소 필수), (d) 거절(구성이 문서에 없어 문장을 만들지 않음).
- 꺼짐 9개(`--sourced-rules-only`): R-EARS-WHERE, R-ADV-WHERE, R-SP-AFTERUNTIL, R-SP-RESP, R-SP-PREC, R-SP-BRESP, R-SP-BINV, R-SP-MINDUR, R-DEFTIME. 근거를 만들 수 없는 사상이므로 도구가 정하지 않고 모델이 정한다(조립은 거절하고 기록, 자유 경로로 이동, +G 규칙문에서도 뺌). R2 arm에서 이 경로로 넘어간 단위 수는 `summary.md`의 fallback 열에 남고, 해석할 때 이 수를 함께 적는다.
- 근거 없는 활성 규칙 0개.
- 공식 파서로 확인된 사실(NuSMV 2.5.4, 판정기 엔진): `upon`, `when`, `if`, `where`는 같은 요구를 낳는다(LTL 동치). 그래서 이 키워드 사이의 선택은 의미에 영향이 없고, 의미를 가르는 선택은 regular 대 holding(`whenever`) 하나뿐이며 이것은 NASA 원문 근거의 `R2-COND-INTENT`가 정한다. `unless p`는 `if !(p)`와 동치(R-BP-UNLESS의 근거). `whenever p ... immediately r`은 `always satisfy p => r`와 동치.
- 결과: v1.4의 도구에는 정답 FRETish나 항목별 결과 관찰에서 도출한 결정이 없다. 따라서 48개 비 FSM 항목은 도구 설계 측면에서 확인 집합으로 쓸 수 있다. 다만 이 항목들의 v4~v8 결과를 실험자(Claude 포함)가 본 적이 있다는 사실과, 의도 가설의 동기가 v1.3과 v8, 020 관찰에서 왔다는 사실은 남는다(가설의 내용은 NASA 문서와 논문 근거).
- 슬롯 프롬프트의 이름 규칙 NM-1과 사전 규칙 D-1~D-4는 +R2 arm에만 있는 표면 형식 규칙이다. 식별자 모양은 공식 문서의 식별자 제한을 따르고, 이름 선택의 영향은 판정에서 사전 이름으로 정렬한 뒤 남는 INSTRUMENT_UND_NM 건수와 자유 개명 건수로 매 실행마다 측정해 보고한다.
- +R2 타이밍 슬롯의 선택 절차 V-2, V-3은 `--tm-source-only`로 제거한다(v1.3에는 있었음).
- 단계 A(템플릿 변환)는 `--stage-a-from`으로 v1.3 출력을 재사용해 v1.3 대 v1.4 차이가 변환 재생성 잡음을 포함하지 않게 한다(프롬프트 해시가 같을 때만 재사용, 다르면 중단).
- 판정 엔진 수치는 샌드박스에서 직접 빌드한 NuSMV 2.5.4로 냈다(대조 결과는 `/tmp` 산출물이 아니라 `analysis` 폴더와 보고서에 복사해 보존한다). Mac의 NuSMV 버전이 다르면 대조(`controls`)를 같은 명령으로 다시 낸다.
- 모델은 한 가지다(sonnet).
