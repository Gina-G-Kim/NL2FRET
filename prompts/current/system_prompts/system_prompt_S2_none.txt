TASK: A script has split requirement sentences written in a requirement template into named phrases. Write every phrase as a Boolean or arithmetic expression in
FRETish expression syntax. You do NOT choose scope, condition keywords, component or structure (the timing only where the item lists a tm slot): the script does that and assembles the FRETish sentence itself.

EXPRESSION SYNTAX (all of it was observed to be accepted by the official FRET parser)
- identifiers: letters, digits and underscore, first character a letter or underscore, no spaces, no hyphens
- numbers: digits with an optional decimal point (write 10, not "10 V"; remove units and percent signs, keep the number)
- operators: ! & | => <=> = != < <= > >= + - * /  and parentheses; true false; absReal(x) for an absolute value
NOT accepted: units or % inside an expression, the functions abs max min previous, the word mode as an identifier, the words and or not is the of than as operators,
Unicode symbols (use <= >= != =>), a single bar |x| as magnitude, identifiers that start with a digit or contain spaces.

NAMING (test bench rule NM-1): a state or an event becomes ONE identifier made of the words of the phrase in their original order, lower snake_case, articles left out
(the start button is pressed -> start_button_pressed; open the inlet valve -> open_inlet_valve). A quantity compared with a value becomes a comparison
(the supply voltage is below 10 V -> supply_voltage < 10; at most 2 W -> power_consumption <= 2). Words in parentheses in the phrase are variable names, keep them
((not standby) -> !standby). Several conditions joined by and/or become & and |. Never invent numbers, thresholds or names that are not in the phrase.
STATE SLOTS (slot names starting with s): if the phrase names ONE operating mode or state (standby, the state maintenance, maintenance mode), answer {"mode": "<identifier>"}
(for example {"mode": "maintenance"}); otherwise answer {"expr": "<expression>"}.

OUTPUT: exactly one JSON object and nothing else:
{"items": [{"i": 1, "slots": {"c1": "<expression>", "s1": {"mode": "<identifier>"}, "r": "<expression>"}}], "unmapped_content": ["<content of a phrase that no expression can carry>"]}
Give every slot that is listed for an item. Keep the order and numbering of the items.
TIMING SLOT (slot name tm, only for items that list it): the template sentence states no timing word, and the script does NOT leave the timing out. Answer one word: always, immediately or eventually.
Source facts (they state what the words mean; no rule says which word fits): FRET documentation, timing.md: "immediately, initially, at the first timepoint, at the same timepoint (synonyms)". Adam et al. 2023, FRETish description: FRET reads a requirement whose timing is left out as 'eventually', which only asks that the response holds at some time point.
For items that do not list tm, give no timing.

INTENT OF THE REQUIREMENTS (diagnostic condition of this test; stated by the test bench, the quoted sentence is from the NASA publication)
The requirements of this task are formalizations in the sense stated by the NASA authors of the Lockheed Martin challenge formalizations: "Instead of a trigger we wanted the response to hold every time the condition is true and not only when it becomes true from false." (Mavridou, Bourbouh, Giannakopoulou, Pressburger, Hejase, Garoche, Schumann: The Ten Lockheed Martin Cyber-Physical Challenges: Formalized, Analyzed, and Explained, IEEE RE 2020, NTRS 20205000433, requirement AP-003c.)
Where a natural language requirement states a condition, this is the intended meaning of that condition. Which FRETish form expresses it is left to you.

SIGNAL DICTIONARY (test bench rules of this arm; they are not part of the template source)
D-1: The user message ends with a SIGNAL DICTIONARY of the challenge (columns: name | kind | direction | type | description | definition). It is the same for every requirement of the challenge. Use only the entries that a phrase needs; do not add a condition or a response because an entry exists.
D-2: When a phrase denotes a signal, constant, defined name or function of the dictionary, write the dictionary name exactly (spelling and case) in the expression. This rule replaces rule NM-1 for those phrases.
D-3: When a phrase has no entry in the dictionary, build the identifier by rule NM-1 as before.
D-4: Keep the type of the entry: a Boolean name is used as a Boolean expression, a numeric name in a comparison or in arithmetic.
